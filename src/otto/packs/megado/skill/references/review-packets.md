# Assemble a bounded review packet from existing evidence

The active run selects the scope, trigger, reviewer role and ceiling. Assembly is not a model review and never creates an implicit stage. Use the packet template only for an actual selected review. Tests-only acceptance needs a compact criterion/evidence/owner record, not a pretend reviewer packet.

Resolve the exact adopted policy/skill/rubric, criteria and candidate. Include: full concise North Star; outcome/authority/non-goals; task/criterion scope; downside and what tests/actual use already show; the remaining question the reviewer can settle; frozen source/artifact/dependency identities; observed test receipts and real-use evidence; prior concrete issues and dispositions; affected correction scope. Missing evidence is marked MISSING, not silently omitted.

Provide an input manifest with accessible exact paths/revisions/digests. Reuse the existing census rather than inventory the entire repository again. Link bulky records and allow scoped inspection; do not dump whole private transcripts or hide a meaningful gap in truncation. Role permissions and blinded inputs remain filtered. Continuing unrelated work does not need to stop while a packet is assembled.

First review covers its selected scope with the full contract available. Repeats ask only the changed material question and affected dependencies. Do not request a fresh strategy after a mechanical correction. The expected outcome is a justified result, not a target number of findings.

Mechanical assembly should use one maintained operation with an explicit input list, expected identities and a distinct packet-root variable. Validate root/path shape and finalized receipt references before an expensive copy/hash pass. Reuse unchanged frozen inputs where the selected review contract permits; preserve failed drafts without treating assembler bugs as product failures or starting another review stage.

For file-mode work without an existing supported assembler, the optional [snapshot helper](../scripts/review_packet.py) provides this mechanical step. A selection JSON contains `inputs`, each with a relative `path`, expected lowercase `sha256`, and `role` (`candidate`, `authority`, `evidence`, or `observation`). Select only authorized relevant files; resolve finalized identities from their actual records. Run `python scripts/review_packet.py assemble --source-root ROOT --selection SELECTION.json --output NEW_PACKET`, then `python scripts/review_packet.py verify --packet NEW_PACKET` when its identity needs checking. Paths are relative to the skill directory for the command; ROOT and output may be absolute. Output parents must exist. Existing output directories, stale inputs, traversal and symlink inputs are rejected. Assembly failure leaves an unaccepted draft; use a new destination after correction. Verification checks selected snapshot bytes and explicit root, not current source applicability, semantic completeness, authorization or a reviewer verdict. The helper is optional, creates no native owner record, and must not replace an established frozen-packet format or become a migration prerequisite for an active run.

The report keeps operational invocation success separate from verdict. Each actionable finding has stable ID, class, exact evidence, relevant criterion, proposed correction and independent normal/XHARD routing rationale. Optional/out-of-scope/stale findings do not get a mandatory correction route. If closure can be purely observable, state its rule now: named check, expected result, candidate/criteria basis and allowed correction scope. Otherwise require judgment. Do not let the implementer rewrite the closure rule later to bypass the finding.

A model invocation counts even if UNKNOWN; rendering or validating this packet does not. Do not relabel an acceptance review as oracle/process advice. Fresh normal review uses the selected Luna Extra High profile; XHARD review uses Sol High; whole-system or oracle work uses the selected Astra profile. A missing model is an explicit blocked invocation, never a silent substitute.
