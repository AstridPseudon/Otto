# D03 invocation and caller boundary

The owner-issued `direction_context_reader` uses the D01 fixed binding and D02
exact scope/assignment adoption resolver. It is read-only and permission-scoped;
ordinary consumers receive no bind/adopt capability. Each applicable bound
owner, project, task or enduring responsibility is mandatory. D02's existing
scope authorization remains authoritative: a project-scoped assignment cannot
consume an unrelated task's direction by naming that task. Unbound scopes do
not create a new prerequisite. Generic guides and supporting refs keep their
existing freshness behavior. Exact authorized direction inputs keep their pins
when a newer draft exists.

The shared canonical operating-brief builder and every canonical role-runtime
preparation call carry attributed direction, independently of optional role
introductions, instruction overrides and explicit context-ref selections.
Worker delegation includes shared scope inputs and excludes parent-specific
responsibility inputs; the child retains independent custody. Enabled advisor
uses the same composition with existing pairing/allowance gates. Disabled
advisor remains inert through existing setup policy. Continuation and
replacement use current assignment/generation/mandate/native fences. The
launch summaries are informational and never credentials. Fresh-session native
IDs become known through inert initialization and exact owner delivery; a null
ID in the initial projection does not claim a pre-existing session binding.

`HostCallerBinding` is supplied by an independently trusted host ingress, never
parsed from tool JSON, prompt text or environment variables. `ExecutionHost`
passes the actual file or accepted socket handle to that injected host hook on
each dispatch. `ExecutionApplication.caller_context` joins the authenticated
actor to current canonical assignment, generation, responsibility and exact
admitted native occurrence. Native IDs are qualified by the recorded adapter
route. Missing, stale, unsupported, reused or unverified bindings fail before
the command handler. Current assignment membership/access/direction is rechecked without provider
calls. Ordinary project edits and the supported resource-adoption base relation
refresh the read projection while retaining original occurrence pins. Commands
still perform their own readiness and effect-admission checks. Owner reopen uses the same durable records; a new connection still
requires the host to authenticate its binding.

`effective-context` / `whoami` are bounded host command reads with no required
agent ID. Optional `caller_*` claims and `logical_agent_id` must agree with the
resolved caller; body-provided caller contexts are rejected. Ordinary command
`principal`, project/task/assignment fields remain target correlation. An
identity-bearing host requires caller-aware authorization before dispatch.
`ManagerJourneyService.authorize_caller` requires its current manager custody;
children and peers cannot reuse that authority or the same payload. Replies
label caller and explicit targets separately; existing owner receipts and
replay rules remain the authority for effects. No caller registry, credentials,
global current-agent variable or context/history store is introduced.

Covered source routes: owner-issued manager, worker/executor, orchestrator,
enabled-advisor, retained canonical callback, continuation and replacement;
in-process host dispatch plus file-IPC and optional Unix-socket ingress hooks.
Focused tests use disposable owner Stores and fake native providers; adapter
variants demonstrate the shared ingress contract only. Exact occurrence reads
are bounded; detecting native-session reuse uses existing Due inventory, whose
current implementation reconstructs records from retained events.

Not established here: authentication of arbitrary same-user file writers or
socket peers, access isolation for cached response files, independent OS or
provider credentials, the neutral serialized Herzchen command facade, other
external helpers, installed CLI aliases, or live connected caller isolation.
Unconfigured transports remain the existing explicit owner-custody lane and
return an unavailable binding for agent identity reads/claims. The installed
host must supply a production trusted ingress and adopt the candidate before
D06 can prove authentication. D04 update/future-boundary composition and D05
authoring/history/overview UX remain separate responsibilities. No owner state,
runtime, publication or acceptance is changed by this source implementation.
