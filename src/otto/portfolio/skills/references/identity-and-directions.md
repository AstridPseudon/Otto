# Identity and directions

Use your installed client's help. Managed native clients expose `whoami` and
`effective-context`; the lower-level portfolio CLI groups these under
`direction` and requires explicit refs. Do not mix their arguments.

`whoami` identifies the caller/binding; `effective-context` shows adopted inputs.
Read actual model/profile selection separately. External-owner authority is not
native identity. Read-only external-root leaves may lack a managed socket: use
delivered owner-bound context and report native reads unavailable.

## Changing instructions

Latest text, scope adoption and assignment adoption can differ:

1. Read current direction, subject, assignment/generation and revision refs.
2. `direction draft` saves without adopting; `direction update` explicitly adopts
   under current guards. Use `initial-bind` only for an unbound responsibility.
3. Scope adoption may succeed while assignment refresh remains partial. The
   generic CLI supplies no assignment actor; use the authorized Work adoption
   route with the complete BASE resources at an eligible queued/reassigned boundary.
4. Use host-supported synchronization where provided; verify adopted direction
   and effective context. Report partial/held outcomes and retain their handles.

Use `read`, `history` and bounded `overview` to investigate differences. Callers
without authoring authority propose changes to their owner. File edits and skill
installs are not adoption. Preserve committed effects; finish only missing steps.
Do not interrupt healthy execution solely for a documentation update.
