# Execution mechanics: source, proof and safe publication

Review timing, profile and counts come from the active run and pragmatic-review.md, not this reference. Planning-only inspection remains read-only. A chosen source snapshot must include or explicitly exclude authoritative dirt with preservation, not silently assume HEAD captures it.

## Before source mutation

Record invoking repository/root, actual ref/commit/tree, staged/unstaged/untracked state, worktrees, remotes, relevant dependency/runtime identity, actual authority and protected local work. Keep one declared control root and a separately identified execution worktree. Do not reset, stash, clean or broad-stage unrelated dirt. Repository-local ignoring of `.otto` does not mean its live database or transcripts should be force-added. Output receipts exclude credentials.

Use one isolated write owner per overlapping surface, disjoint workers where contracts are ready, and explicit source handoffs. An owner may hold several related responsibilities; one worker never receives conflicting orders from two managers. A commit hash does not prove tests ran, and a Git worktree is not a security sandbox.

Before expensive work check real storage/resource headroom and expected fan-out. Do not use a small read-only query as an excuse for a broad audit. Stop equivalent retries after disk or environment failure until the cause and partial output are checked. Never reclaim another project's files, active source, user media or required evidence as a shortcut.

## Native agent lifecycle

The manager records each native launch ID against its assignment and generation, collects and accepts the result, then closes an eligible completed worker through an actually exposed supported host operation. Completion is not closure. Workers return their result, native identity, changed files, verification and unresolved responsibility to the manager; they do not declare their own acceptance or slot release. Preserve results and history, active workers/managers, and unresolved responsibilities. Retire a manager only after project closeout and owned schedule cleanup.

Before launch, immediately on admission failure, and during hourly supervision, reconcile completed and stranded sessions and pending delivery. Respect actual concurrency and leave coordination capacity. Resolve exact eligible IDs from launch records or supported inventory. Where exposed, call `multi_agent_v1__close_agent({target: exact_id})`, await supported shutdown readback (`not_found` was observed in the qualified recovery), then verify removal from the owning root inventory and successful supported admission. The close return is a previous status, not shutdown proof. A root without close delegates the exact authorized target to the manager with that tool; do not assume incompatible pools. Scope rejection remains a limitation. Stop/interrupt/archive/unsubscribe do not prove release. Record each result honestly; use no history deletion, raw app database edits, process killing, replacement pools or limit bypass.

## Manager communication

Every newly created manager follows [the manager communication policy](manager-communication.md). Routine launches, findings, decisions, failures and completions are recorded in canonical Otto owner records and run evidence; routine coordination goes directly between the manager and its workers or peer managers. Managers continue ready work without waiting for hourly supervision. The root pulls one consolidated portfolio summary hourly. A manager interrupts the root only for an urgent actual user decision or imminent material loss or equivalent time-critical risk.

## Incremental commits and publication

Commit coherent named source/test increments after relevant focused checks where practical and before handoffs or substantial pauses. A preservation commit may contain unfinished work, but label WIP, failed/not-run checks and open obligations honestly. Code-ready handoff includes passing relevant checks and consumed source/contract identities. Do not wait for model review to commit; a checkpoint is not acceptance.

Bind input upstream separately from approved publication fork/new owned repository, actual push URL and explicit allowed branch/ref. Ownership of a GitHub account or a remote named origin is not permission. Resolve actual push URLs and rewriting, workflow/protection side effects and intended content before each push. No bare push, wildcard/all/mirror/tag push, force/protection bypass or implicit upstream PR. In the current portfolio upstreams are read-only. Elsewhere the actual adopted mandate governs; this skill never supplies a new target grant.

Inspect only the named staging paths and staged diff; protect secrets, unowned source, large artifacts and live control data. Local commits remain useful during network/permission failure; report that no remote checkpoint exists. Reconcile a possibly successful push by exact remote/ref/head before retry. Do not select a different remote because the approved one is unavailable.

## Evidence ladder

Run focused fixtures during implementation; affected integration when contracts converge; the broad affected campaign on a settled candidate; and costly/live/full-scale operations only when a criterion needs them and the actual environment/budget allows it. Prefer tests or real tool use over reviews for observable questions. Reuse existing passing evidence only when candidate, inputs and relevant environment still match. After a correction rerun its affected closure, not unrelated suites.

Capture exact source, command/tool, relevant inputs/environment, output/result, duration and evidence reference through existing tool receipts or generated records where supported. Capture assignment identity once and link operation results to it; create a new package or pin only for a changed relevant contract, an actual review candidate or a consequential operation boundary. Unrelated status prose and bookkeeping do not invalidate proof. Missing relevant identity remains a real evidence gap; never suppress an actual mismatch. Distinguish retained baseline failures, new regressions and missing proof. Never delete a safety assertion to make extraction green. For a real transition, preserve valuable data, use a representative fixture, and perform one necessary source/data inventory and proportionate rehearsal. Do not build a migration framework merely because there might someday be users.

## Evidence identity and scoped restrictions

Keep executable/dependency identities, actual authority, immutable observations and rolling narrative distinct. Pin only the semantic inputs required by the operation. An observation records its cutoff; its preparation state is not a perpetual assertion about current state. Reference preserved history rather than copying current-looking counters and gap prose into executable manifests. A status edit does not revoke a passing test or require stopping a worker. Preserve existing bound snapshots; reconcile affected administrative references once at the next required handoff without ignoring a true validator mismatch.

Historical records are retained for reconstruction; they become execution dependencies only when their semantic content actually governs the operation. Do not recursively bind every predecessor report or ruling merely because it was consulted. Recording a recommendation does not adopt a new requirement.

When verification machinery repeatedly fails, exercise its connected producer/consumer sequence with realistic evolving state before another expensive operation. Check whether an earlier successful step creates legitimate output that a later predicate incorrectly rejects. Reuse a representative fixture rather than introducing a universal harness or mandatory review stage.

When a restriction blocks useful work, identify its origin and scope in the existing brief: user/platform boundary, adopted authority decision, or local assignment choice. The accountable manager may narrow or revise its own assignment choice within the mandate; do not escalate it as missing user permission. Where relevant evidence is already lawfully captured, offer the minimum scoped record/field access or a provenance-preserving extract to its authorized consumer. Do not rediscover unrelated sessions, fabricate native records or expose private content merely to resolve a schema question. Observed version-bound shapes remain distinct from a general protocol guarantee; unsupported shapes fail closed.

## Local correction and operational uncertainty

For a failed isolated fixture, preserve its evidence, confirm the previous process has stopped, and inspect its known state through supported readers. Continue an in-scope repair in a fresh disposable namespace under the existing assignment; no new oracle ruling or one-use coordinator pin is needed merely to read, edit or retry locally. Do not overwrite the failed fixture or call an unresolved result successful. Treat any possible contact with operational state or external effects as operational until its isolation is established.

Uncertain live writes, provider invocations and publication attempts require reconciliation against the actual target before retry. A new request key or namespace is not permission to duplicate external effects. Local retry freedom neither waives a required acceptance gate nor increases an explicit spending or attempt limit.

## Frozen review

When an adopted review is actually due, freeze the exact reviewed candidate and relevant evidence; stop its mutators. Normally commit in the approved execution worktree; where commit authority is absent, create an explicit non-destructive snapshot with a content manifest. The read-only reviewer has independent context and output/scratch outside frozen source. Verify unchanged candidate/evidence identities before accepting applicability. An old PASS cannot certify changed inputs without a recorded valid basis.

The packet includes complete concise North Star, current mandate, precise criteria and selected risk/question, source/diff, actual checks, current concrete finding/oracle dispositions and relevant dependency closure. Do not seed the reviewer with persuasive prior PASS narratives. Findings are not criteria expansions. Technical reviewers are leaves; no recursive panels.

## Finish

Map every promised outcome to observed evidence; distinguish complete, blocked, failed, undetermined, retryable and needs-authority. Acceptance and remote publication are different acts. The final broad campaign and selected holistic judgment precede promotion. Integration chooses actual producer/consumer order and expected heads; several repositories are not atomic. If two succeed and one fails, preserve the partial state and reconcile. Do not automatically force or revert history.

Verify final allowed targets and tree/dependency equivalence (including squash/rebase effects), run the small supported-entrypoint smoke and return a source manifest. A source merge is not package publication, production deployment or old-data migration. Hand off the actual remaining limits, pending work, recovery route and canonical state location.

Discovery-index scripts may be used in the file-based environment if present and verified; failure of a convenience index is not an acceptance gate. Native Otto/Herzchen uses its actual project discovery API. Never depend on an unavailable helper to create fictional execution evidence.

## Maintained Otto operator surface

The maintained execution composition is owner-bound: construct it through
`PortfolioOwnerBootstrap.execution_application(...)` and use its
`ExecutionApplication` methods for manager preparation, start, continuation,
recovery, and public acceptance. Scheduled advisor work uses
`AdvisorExecution` and `ExecutionHost` through the same bootstrap; it does not
create a second Store, scheduler, or workflow engine.

The ordinary diagnostic path is deliberately split by authority:

```sh
python -m otto.portfolio.cli --help
python -m otto.portfolio.cli help --format text
python manager_ctl.py --help
python controller/serve_manager_owner.py
python controller/inspect_project.py
python controller/read_manager_status.py
```

The first two commands describe and exercise scoped owner-backed reads, briefs,
pairing, acceptance, and the maintained execution composition. `manager_ctl.py`
is the thin owner command client for an already running command service; it does
not start a legacy manager. `serve_manager_owner.py` keeps the existing
`ManagerCommandServer`/`ExecutionHost` custody and file-IPC surface alive until
its explicit stop file; it launches no manager, worker or advisor. The live
service must own the Store exclusively. `inspect_project.py` and `read_manager_status.py`
are current-state evidence readers. Status reads the exact persisted schedule
with `read_due(schedule_id)`; it must not enumerate the entire historical Due
stream merely to render current state.

For an existing advisor occurrence, reconcile first and preserve its exact
schedule, assignment, generation, native binding, decision state, allowance,
and gateway/provider evidence. Only then may the owner-admitted controller
prepare or wake the authorized occurrence. A delivered decision is never
resent because a follow-up read is pending. Awaited dispatch and fixture
callbacks are evidence of those mechanisms only; unattended timer behavior
requires an actual configured host automation and its persisted readback.
