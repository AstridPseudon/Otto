**Verdict: simplify the execution API, but don’t claim the proposed macOS group-plus-tag fallback guarantees G1 and G2.** It is reasonable for ordinary task cleanup on a single-user machine if escaped processes are reported as a limitation. As written, it also misses host-crash cleanup and retains a PID-reuse race. The current custody path is more exact while its owner is alive, but its observation, lock and deadline machinery has real failure costs ([process_group.py](${ORIGINAL_HOME}/Developer/astrid-video/astrid-local/main-20261015/Astrid/astrid/core/execution/process_group.py:391), [custody_broker.py](${ORIGINAL_HOME}/Developer/astrid-video/astrid-local/main-20261015/Astrid/astrid/core/execution/custody_broker.py:2799)).

**Failure cases**

- **PID reuse / stranger signals:** A tag, UID, and “started after container creation” nominate a process; they don’t make its PID safe to signal. On macOS, a process can exit and its PID be reused between the final check and `kill(pid)`. Second-resolution start times make that worse. Rechecking narrows the race but does not close it. Current custody retains incarnation-bound signal authority per observed process; it does not rely on a census as signal authority ([process_group.py](${ORIGINAL_HOME}/Developer/astrid-video/astrid-local/main-20261015/Astrid/astrid/core/execution/process_group.py:327), [custody_broker.py](${ORIGINAL_HOME}/Developer/astrid-video/astrid-local/main-20261015/Astrid/astrid/core/execution/custody_broker.py:3718)).
- **Reparenting / `setsid` / cleared environment:** A tag sweep can find reparented or session-detached children only while they retain the tag. A child that clears its environment and calls `setsid` evades both mechanisms. The proposal explicitly accepts deliberate evasion; ordinary tools that daemonize or sanitize environments could trigger the same failure without malice.
- **Owner or host crash:** A lifeline can tell a cooperative host its owner disappeared. It cannot kill the host’s task containers if those handles lived only in the crashed host. macOS groups don’t die when their parent exits; tagged survivors still need a live sweeper. Linux cgroups and Windows Job Objects can improve this where their lifetime is actually tied to the owner.
- **Sleep, reboot, restart:** Sleep pauses survivors; it doesn’t clean them. Reboot clears local processes. A runtime restart is safe only if the separate resident owner survives and retains the handles. The proposal doesn’t specify recovery if that owner itself crashes.
- **Two stacks / Otto-heavy sweeps:** Per-container unique tags and separate data-root owners should avoid cross-stack interference, but only if the tag is never reused and sweeps are scoped to that owner. Strip `OTTO_HEAVY_LEASE` at every owned launch: the reported sweep already killed a host that inherited it.

**Smallest safeguards worth keeping:** one lifecycle API and one owner that retains every task and engine handle, including across host failure; OS-native containment where available (cgroup/Job Object); and on macOS, retained incarnation-bound signaling for observed descendants. Keep groups for bulk termination, with tags only as discovery hints—not signal authority. If the owner dies, report cleanup as unresolved rather than claiming G1. Make census delays retryable so transient load doesn’t permanently latch the host.

That preserves the useful abstraction without requiring every task to prove perfect descendant history on a one-second deadline. The proposal’s host-owner and narrowed render validation are good directions; its macOS fallback and host-crash story need tightening before adopting the stated guarantees.
