## 2. Threat model (one page; the decision everything else follows from)

The setting is a single user's machine. Astrid guarantees two things:
- **G1:** no process Astrid starts outlives the task, or the host, that started it.
- **G2:** Astrid never signals a process it did not start.

Not defended: a process running as the same user that deliberately escapes, for example by clearing its environment and then calling setsid and daemonizing. `SECURITY.md` already states that pack code runs with the user's full privileges, so the custody layer cannot be stopping an adversary. What it must actually prevent is (a) leaked helpers, and (b) PID reuse or misidentification leading us to signal a stranger.

## 3. Design

### 3.1 One primitive: the container

`Container` is the only process-lifecycle API. Every capability execution, of every task type, is exactly one container.

```
c = Container.spawn(argv, env=..., cwd=..., label=...)   # leader = new session/group; tag injected
c.members() -> [Proc]        # one census: our group/session + our tag, started after c.created
c.stop(grace=…) -> Report    # TERM group → wait → KILL group → sweep tagged → final census
c.close()                    # reap leader last (keeps the pgid from being recycled until here)
```

How it meets the two guarantees:
- **G1, cleanup:** the group kill and the tag sweep. Done means a single final census finds nothing that matches.
- **G2, never signal a stranger:** a candidate is signalled only if all three hold:
  - it is in our group or session, or carries our tag;
  - its start time is at or after the container's creation;
  - its uid is ours.

  Everything is re-checked immediately before each signal. The leader is never reaped before the end, so the pgid cannot be recycled.

Failure semantics:
- **No sticky latch.** If survivors remain after KILL, the report names them (pid, command, start time). The owner retries, and an explicit operator `resolve` exists.
- **No sub-second budgets on correctness paths.** Deadlines exist only for liveness, measured in minutes, and they never decide whether cleanup was proven.

Per-platform backends, chosen at runtime by capability:
- **macOS:** session/group, plus the tag in env, plus start-time-checked sweep. A launchd job per container is optional.
- **Linux:** a cgroup v2 scope when available (`systemd-run --user --scope`), which gives exact membership and `cgroup.kill`. Otherwise the same group, tag and sweep as macOS.
- **Windows:** a Job Object with kill-on-close.
- **RunPod / containers:** the container runtime is the container.

The guarantee is the same everywhere; only the mechanism gets stronger where the OS offers it.

### 3.2 One owner per lifecycle

- **The host owner.** A resident Astrid process, one per data root, holds the host's container.
  - CLIs ask it over a 0600 unix socket and never launch or retire a host themselves.
  - The host gets a lifeline pipe, so it cannot outlive its owner.
  - The owner spawns without per-job tags such as `OTTO_HEAVY_LEASE`.
  - This is built and unit-tested on `fix/main-host-owner` 928a85cd. The Runtime stays neutral: there is no Runtime→Astrid import.
- **Tasks are owned by the host,** one container per attempt.
- **Long-lived engines are containers owned by the host with an explicit lease.** These are VibeComfy and the Remotion frame owner, which today escapes the tree via `launchctl submit`. The escape stops being necessary.

### 3.3 Validate what you use, when you use it

The Remotion and registry validation runs at render time, for the one context the render actually runs in, and is cached by a digest of its declared inputs. Today it runs at every host launch, across all 223 worker contexts.

### 3.4 Identity by declared inputs, not ambient state

Reuse is decided by a digest of declared inputs plus the toolchain. Authority is the owner's handle. Neither hashes ambient environment or argv. That class of check produced the GIT_EDITOR refusal, the Codex attempt-home failure, and the framework-argv mismatch.

### 3.5 The gate

Main accepts a change only if the film journey passes on a *normally loaded* machine: image, edit, publish, full render. An exclusive quiet window does not count.

## 4. What it deletes (estimate)

- **custody_broker.py:** most of its per-descendant path (~3,000 of 3,933 lines), covering:
  - audit-token capture and designation files for ordinary commands;
  - candidate reconciliation;
  - the observer thread;
  - the 1 s cap;
  - the cleanup-uncertain latch.

  Tokens stay only where a control peer genuinely needs them, if anywhere.
- **process_group.py:** the observation loop, `_observe_tree` reconciliation, and the busy and starvation handling.
- **host_bootstrap.py:** cross-process recognition (native argv pins, framework re-exec matching), marker forensics, and startup budget special cases.
- **remotion_runtime.py:** most of the launch-transaction probes.
- **Runtime's `custody_broker.py`** (1,689 lines), if only the unused local-worker route needs it.

Net: roughly −4,000 to −5,000 lines against about +1,000 lines. Most of the +1,000 already exists: V1 (`claude/task-container-custody` dbff7f83, about 500 lines, the same interface as `popen_owned_group`, `terminate_group` and `verify_tree_absent`) plus today's owner.

## 5. Migration (small steps, film-gated)

1. Land the host owner.
2. Put `Container` behind the existing `process_group` API (`popen_owned_group`, `observe_tree`, `terminate_tree`, `verify_tree_absent`), so generic_host barely changes. Port V1 for this step.
3. Prove it with a full-film render on a normally busy machine.
4. Delete the per-descendant path, the latch and the observer.
5. Narrow validation to render time.
6. Turn on the gate.

## 6. What we give up, and your earlier objections

- **"Group-empty does not discharge escaped or reparented descendants."** The tag sweep catches anything reparented or setsid'd that keeps its environment. The threat model explicitly gives up only "deliberately clears env *and* detaches", which a same-user process could do anyway.
- **"No env-tag signal authority."** The tag only nominates candidates. Signalling requires the tag or the group, plus a start time after container creation, plus our uid, all re-checked at signal time.
- **"No budget inflation."** Agreed. This proposal removes budgets from correctness paths rather than inflating them.
