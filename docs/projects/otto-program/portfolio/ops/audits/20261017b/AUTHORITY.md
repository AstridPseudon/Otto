## 1. Findings

### 1. A manager can trigger another project’s retained execution through the shared file lane

**Evidence:** The product uses one shared IPC directory with file compatibility enabled ([product_service.py:1250](/private/tmp/otto-audit-tree/src/otto/hostctl/product_service.py:1250), [product_service.py:1288](/private/tmp/otto-audit-tree/src/otto/hostctl/product_service.py:1288)). Every launched manager receives that directory as a write root ([serve.py:441](/private/tmp/otto-audit-tree/src/otto/hostctl/serve.py:441)); the sandbox permits writes there ([claude.py:110](/private/tmp/otto-audit-tree/src/herzchen/fleet/hosts/claude.py:110)). File compatibility skips native caller binding and treats the request as owner custody ([execution_host.py:1259](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1259)). For retained commands, the router selects a project from the submitted `schedule_id` without an owner-route grant ([project_services.py:165](/private/tmp/otto-audit-tree/src/otto/portfolio/project_services.py:165)). The selected service checks that the task, worker principal and schedule match *its* retained state, then calls `app.start`; it does not identify the file submitter ([manager_journey_service.py:1086](/private/tmp/otto-audit-tree/src/otto/portfolio/manager_journey_service.py:1086)).

**Scenario:** Project B has an admitted, ready, prepared worker. Manager A writes a raw `start-retained-worker` request containing B’s task, worker principal and schedule ID to the shared directory. B’s worker starts under B’s installed manager authority. **Inference:** A can obtain the tuple from B’s saved service state ([serve.py:53](/private/tmp/otto-audit-tree/src/otto/hostctl/serve.py:53), [serve.py:174](/private/tmp/otto-audit-tree/src/otto/hostctl/serve.py:174), [manager_journey_service.py:2451](/private/tmp/otto-audit-tree/src/otto/portfolio/manager_journey_service.py:2451)): these processes share an OS account, and the manager sandbox allows reads by default ([claude.py:110](/private/tmp/otto-audit-tree/src/herzchen/fleet/hosts/claude.py:110)). This lets one project’s agent advance another project’s work. The same unbound retained route includes manager result continuations ([project_services.py:27](/private/tmp/otto-audit-tree/src/otto/portfolio/project_services.py:27)).

**Proposed fix row — xhard:** Retained starts and continuations must carry owner-issued, single-use provenance unavailable in manager-writable storage. Scope manager file writes to their own requests. Files: `hostctl/product_service.py`, `hostctl/serve.py`, `portfolio/project_services.py`, `portfolio/execution_host.py`. **Acceptance check:** with A and B installed and B’s worker prepared, a raw B start submitted from A’s granted directory is refused and B’s launch count remains zero; the owner’s legitimate retained B start still executes once, including after recovery. A plausible fix that merely rejects all file starts would break the owner’s retained callback and restart paths.

### 2. Agent roles can take reserved operator or owner actor names

**Evidence:** A host’s `project activate --manager-principal` passes the supplied name into the plan, then materializes a manager assignment with that principal ([cli.py:481](/private/tmp/otto-audit-tree/src/otto/hostctl/cli.py:481), [register.py:455](/private/tmp/otto-audit-tree/src/otto/hostctl/register.py:455)). A manager’s `run-worker --principal` checks only for nonblank text and uses it for the worker assignment ([manager_journey_service.py:2219](/private/tmp/otto-audit-tree/src/otto/portfolio/manager_journey_service.py:2219), [execution.py:459](/private/tmp/otto-audit-tree/src/otto/portfolio/execution.py:459)). Native caller identity is then bound to that assignment principal ([identity_context.py:41](/private/tmp/otto-audit-tree/src/otto/portfolio/identity_context.py:41)). Separately, `admit-host` rejects an operator-name collision but permits the owner actor’s name ([service.py:526](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:526)); installation validation also omits an owner-versus-host check ([config.py:139](/private/tmp/otto-audit-tree/src/otto/hostctl/config.py:139)).

**Scenario:** An admitted host activates a manager named exactly as the installation’s operator. That agent’s bound caller identity names the operator, and its saved manager note is recorded using `authenticated_actor(state["manager"])` ([manager_journey_service.py:353](/private/tmp/otto-audit-tree/src/otto/portfolio/manager_journey_service.py:353)). A manager can likewise name the operator as a worker. These are concrete identity and audit-attribution failures. I found **no evidence** that name collision alone bypasses the owner lane’s presence check for task admission or the native role and assignment checks.

**Proposed fix row — normal:** Reserve operator and owner actor IDs at host admission and every agent-role assignment entrance; reject a host principal already assigned to another host. Preserve assignment-scoped worker names where they do not collide with reserved actors. Files: `hostctl/config.py`, `hostctl/service.py`, `hostctl/register.py`, `portfolio/manager_journey_service.py`. **Acceptance check:** admitting a host as the owner, activating a manager as the operator, and submitting a worker as the operator each refuse before assignment creation; ordinary distinct principals still work. Each collision is accepted before the fix.

## 2. Checked and sound

- **Operator:** The owner lane handles operator actions; task admission requires a fresh local presence result and writes as the configured operator ([service.py:405](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:405), [service.py:449](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:449)). The creator fallbacks already have a `FAILCLOSED` row and are omitted here.
- **Host:** File-lane location binds host kind; submitted `home`, `host` and `owner_authorized` fields are discarded. Host manager relay refuses native identity-bearing commands ([service.py:546](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:546), [service.py:597](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:597)).
- **Manager and worker native commands:** The socket checks live process ancestry, birth identity and the exact retained occurrence; the command handler then applies manager or task-scoped worker authorization ([native_caller_ingress.py:131](/private/tmp/otto-audit-tree/src/otto/portfolio/native_caller_ingress.py:131), [identity_context.py:31](/private/tmp/otto-audit-tree/src/otto/portfolio/identity_context.py:31), [manager_journey_service.py:720](/private/tmp/otto-audit-tree/src/otto/portfolio/manager_journey_service.py:720)). Reusing another worker’s principal name does not select that worker’s assignment.
- **Worker MCP:** A live token resolves to one assignment and role; the facade takes the assignment from that grant, and landing takes its lab and task from owner context ([tokens.py:23](/private/tmp/otto-audit-tree/src/herzchen/fleet/tools/tokens.py:23), [facade.py:169](/private/tmp/otto-audit-tree/src/herzchen/fleet/tools/facade.py:169), [facade.py:75](/private/tmp/otto-audit-tree/src/herzchen/fleet/tools/facade.py:75)).
- **Grants and permissions:** Orchestrator reply grants bind one request digest and recheck the current supervisor ([serve.py:670](/private/tmp/otto-audit-tree/src/otto/hostctl/serve.py:670)). File lanes use 0700 directories and 0600 files; the native caller socket is 0600 ([lanes.py:40](/private/tmp/otto-audit-tree/src/otto/hostctl/lanes.py:40), [lanes.py:51](/private/tmp/otto-audit-tree/src/otto/hostctl/lanes.py:51), [execution_host.py:1090](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1090)). The code explicitly does not claim these permissions isolate hostile processes under the same OS account ([lanes.py:8](/private/tmp/otto-audit-tree/src/otto/hostctl/lanes.py:8)).
