1. **The bootstrap gate can merge a commit it did not test.** Evidence: [land.sh:111](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:111) rebases the lab, the gate checks it, but [land.sh:462](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:462) checks only that `canon/main` stayed at `BASE` before merging the *branch name* at line 464. If another actor advances `lab/TASK` during the gate, the later tip is merged and pushed without its check running. **Fix row — normal:** in `ops/bootstrap/land.sh`, pin the tested SHA, verify the lab and branch still name it, and merge that SHA. Acceptance: advance the lab branch after its check; landing must refuse with `canon/main` and the remote unchanged.

2. **Completion evidence can be accepted before the Git landing succeeds.** Evidence: [landing.py:177](/private/tmp/otto-audit-tree/src/herzchen/fleet/landing.py:177) writes assessments and acceptances, and lines 205–210 find the completion gate clear; the final clean-line check and merge occur only at [landing.py:211](/private/tmp/otto-audit-tree/src/herzchen/fleet/landing.py:211). [assignments.py:694](/private/tmp/otto-audit-tree/src/herzchen/domains/work/assignments.py:694) uses the assessment gate for completion without a Git landing check. If the line becomes dirty after acceptance, `done` refuses and retains the lab, but the accepted records remain. **Inference:** a manager supplying those otherwise valid refs can complete work whose commit never landed. This is a sibling of COMPLETECITE: an exact citation still does not prove a merge. **Fix row — xhard:** bind completion to durable proof that the accepted commit reached the configured line; update `landing.py`, `fleet_landing.py`, and the completion predicate. Acceptance: inject a failure after acceptance and before merge; completion refuses, then a retry can land once. A plausible mistake is moving acceptance after merge, which could leave a commit on the line when assessment refuses it.

3. **A later landing can publish an earlier task reported as refused.** Evidence: after a failed push, [land.sh:469](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:469) keeps the local merge and exits before [land.sh:478](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:478) removes its lab and branch. The next task takes that advanced local line as `BASE` at line 108 and, if the remote has not moved, pushes both commits. Thus transient push failure on A → `LAND RESULT: refused`, A’s worktree and branch remain → landing B publishes A. A failure in [otto-lab.sh:26](/private/tmp/otto-audit-tree/ops/bootstrap/otto-lab.sh:26) after a successful push likewise leaves cleanup unfinished. **Fix row — xhard:** make `land.sh` and `otto-lab.sh` reconcile a pending push and cleanup before admitting another landing. Acceptance: fail A’s push once; B cannot publish A until A’s remote state and cleanup are resolved. A plausible mistake is resetting the local merge on a nonzero push when the remote actually accepted it but the response was lost.

4. **A crashed gate leaves a permanent landing lock.** Evidence: [land.sh:93](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:93) creates `ops/land.lock`; [land.sh:21](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:21) removes it only in an EXIT trap. `SIGKILL` or power loss skips the trap, so every later task is told another landing is running. The private `/tmp/l.*` root created at line 97 is also left behind. **Fix row — normal:** use a crash-released lock or verified stale-owner recovery in `land.sh`, with reclamation of its recorded temp root. Acceptance: kill a gate while it holds the lock; a new gate proceeds, while two live gates still cannot overlap.

5. **A wrong checkout can consume a worker turn before landing refuses it.** Evidence: [product_service.py:610](/private/tmp/otto-audit-tree/src/otto/hostctl/product_service.py:610) verifies that the planned branch exists and lines 617–625 prepare its lab, but does not verify the repository has that branch checked out. Only `done` calls the clean, correct-branch check at [landing.py:89](/private/tmp/otto-audit-tree/src/herzchen/fleet/landing.py:89) and [landing.py:322](/private/tmp/otto-audit-tree/src/herzchen/fleet/landing.py:322). Acceptance: wrong-branch and dirty-line cases refuse before a provider call; a correct clean line starts.
