**1. `otto` advertises commands its owner lane rejects.** The installed `otto` entry point parses the full portfolio tree and forwards each verb through `portfolio-operation` ([pyproject.toml:14](/private/tmp/otto-audit-tree/pyproject.toml:14), [portfolio/cli.py:1698](/private/tmp/otto-audit-tree/src/otto/portfolio/cli.py:1698), [portfolio/cli.py:1757](/private/tmp/otto-audit-tree/src/otto/portfolio/cli.py:1757)). The owner accepts only the finite list in [hostctl/portfolio.py:16](/private/tmp/otto-audit-tree/src/otto/hostctl/portfolio.py:16) and rejects other first verbs at [hostctl/service.py:424](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:424). Thus `otto --portfolio P tasks …` or `onboarding create …` parses and sends, then fails before its handler. This strands an agent following the advertised public surface. `otto admit` is additionally dead: its handler always denies ([portfolio/cli.py:147](/private/tmp/otto-audit-tree/src/otto/portfolio/cli.py:147), [portfolio/cli.py:1447](/private/tmp/otto-audit-tree/src/otto/portfolio/cli.py:1447)). **Fix row, xhard:** align public parser/help and authenticated routes; remove `otto admit`, expose only working verbs until others have scoped routes. Files: `portfolio/cli.py`, `hostctl/portfolio.py`, `hostctl/service.py`, CLI tests. Acceptance: every verb advertised by the installed `otto` either completes on its intended principal or is absent; `onboarding create` no longer reaches an unexplained lane denial. Plausible bad fix: allowlisting every parsed verb would grant owner authority to `complete-task` and other guarded effects.

**2. Neither parser registers it ([hostctl/cli.py:75](/private/tmp/otto-audit-tree/src/otto/hostctl/cli.py:75), [hostctl/portfolio.py:38](/private/tmp/otto-audit-tree/src/otto/hostctl/portfolio.py:38)); a test explicitly asserts project sync was removed ([test_hostctl_sync.py:1](/private/tmp/otto-audit-tree/tests/test_hostctl_sync.py:1)). An agent editing a registered bundle reaches a usage error at the required sync step, so the documented workflow cannot proceed. **Fix row, normal:** replace these examples with the current authoring/check-in route and remove the obsolete conflict promises. Files: the cited guides, `docs/host-onboarding.md`, staged Megado guidance. Acceptance: a documentation command audit rejects every unregistered command; the replacement sequence is checked against the parser and owner route. This is separate from the queued A6 deletion of the mirror.

**3. Files: `agents/claude_cli.py`, `fleet/tools/facade.py`, `ops/bootstrap/perch_fake_claude.py`, relevant tests. **4. For the same project and task inputs, an agent must choose among names that yield the same read. **Fix row, normal:** keep `show task` and `tasks`; delete public `task` and `overview` after updating their tests/callers. Files: `portfolio/cli.py`, CLI tests and guidance. Acceptance: retained routes return the same detail/page and removed names are absent from installed help. The explicitly labelled legacy `create-pending`, `read`, and `list` ([portfolio/cli.py:158](/private/tmp/otto-audit-tree/src/otto/portfolio/cli.py:158)) should be retired with their callers, rather than treated as exact aliases.

**5. The installed `otto-gateway` effect verbs have no binding.** Packaging exposes a third script ([pyproject.toml:15](/private/tmp/otto-audit-tree/pyproject.toml:15)) with `invoke`, `resume`, `send`, `cancel`, and `wait` ([otto/cli.py:23](/private/tmp/otto-audit-tree/src/otto/cli.py:23)). Its installed entry point supplies no gateway, so `main` constructs one with binding and authority unavailable ([otto/cli.py:42](/private/tmp/otto-audit-tree/src/otto/cli.py:42)). Those effect commands cannot operate through that script. **Inference:** a checkout-wide caller/document search found no operational use of the script; the gateway class itself is used internally. **Fix row, normal:** remove the public effect verbs, or the entire script if its diagnostic reads have no consumers; retain the internal gateway. Files: `pyproject.toml`, `otto/cli.py`, `tests/test_packaging.py`. Acceptance: packaging exposes no inert effect command while the owner’s injected gateway still works.

**6. One logical mutation key has two flag names.** `otto save --request-id` calls its value a “logical request key” ([portfolio/cli.py:80](/private/tmp/otto-audit-tree/src/otto/portfolio/cli.py:80)), while `ottoctl project register` and manager mutations use `--request-key` ([hostctl/cli.py:77](/private/tmp/otto-audit-tree/src/otto/hostctl/cli.py:77), [manager_client.py:44](/private/tmp/otto-audit-tree/src/otto/hostctl/manager_client.py:44)). An agent applying the usual mutation flag to `otto save` gets a parser error. **Fix row, normal:** accept `--request-key` for logical mutations, temporarily aliasing `--request-id` to the identical value; retain `--request-id` for transport handles such as `command-status`. Files: portfolio parsers, forwarding parser and CLI tests. Acceptance: both save spellings produce the same idempotency key; `command-status --request-id` remains unchanged.
