## 1. Findings

**High — Claude manager process registration reads owner state on the transport thread.**

- **Evidence:** The gateway moves the adapter call to a retained child at [gateway.py:1788](/private/tmp/otto-audit-tree/src/otto/agents/gateway.py:1788) and [execution_host.py:973](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:973). Claude wraps `native_process_observer` only inside that call at [claude_adapter.py:447](/private/tmp/otto-audit-tree/src/otto/agents/claude_adapter.py:447). With no thread-local owner context there, `owner_callback` returns the raw callback ([execution_host.py:1683](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1683)). The observer builds a binding by iterating `state["workers"]` ([native_caller_ingress.py:97](/private/tmp/otto-audit-tree/src/otto/portfolio/native_caller_ingress.py:97), [native_caller_ingress.py:185](/private/tmp/otto-audit-tree/src/otto/portfolio/native_caller_ingress.py:185)); the owner pump can add a worker to that mapping ([manager_journey_service.py:2451](/private/tmp/otto-audit-tree/src/otto/portfolio/manager_journey_service.py:2451)).
- **Failing scenario (inference from the concurrent paths):** A manager process starts while automatic dispatch adds a worker. The observer’s dictionary iteration can raise `RuntimeError: dictionary changed size during iteration`. Claude then terminates the new process before useful input ([claude_cli.py:377](/private/tmp/otto-audit-tree/src/otto/agents/claude_cli.py:377)). A routine concurrent dispatch can therefore fail a manager launch.
- **Proposed fix row — xhard:** Capture and wrap the observer on the owner lane *before* the adapter handoff; run binding construction there and wait for registration before native input. Files: `src/otto/agents/gateway.py`, `src/otto/agents/claude_adapter.py`, and the owner binding site in `src/otto/hostctl/serve.py`. **Acceptance:** a barrier-controlled owner test adds a worker during manager launch, obtains one exact caller binding, and asserts the observer runs on the owner thread; the thread assertion fails before the fix. The cross-component invariant is registration before useful input. A plausible faulty fix would enqueue registration asynchronously, allowing input first. This is a sibling of PINALL’s process-group pin work; that row does not cover caller-binding thread affinity.
