## Findings

1. **An unbounded relay read can close the owner.** [service.py:381](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:381) reads and parses the entire manager response, then expands it as a mapping; [project_service.py:91](/private/tmp/otto-audit-tree/src/otto/hostctl/project_service.py:91) calls this from the active owner poll. **Scenario:** a large valid manager response is copied into owner memory and republished; a valid JSON array raises `TypeError`, which escapes the poll and unwinds the owner loop. `read_text()` also bypasses the lane’s private-file checks. This can interrupt unrelated work. **Fix row — xhard:** bound and validate relay reads, returning a finite response with an exact retained artifact pin. Files: `hostctl/service.py`, `portfolio/manager_journey_client.py`, relay tests. Acceptance: a response over 1 MiB and a JSON array leave the owner serving, with no command replay. Plausible mistake: returning only a summary while claiming the full manager result was delivered.

2. **A crash can leave an unreadable owner locator that prevents restart.** [execution_host.py:1072](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1072) creates the final owner file before writing JSON; [execution_host.py:1031](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1031) refuses an existing file it cannot parse. **Scenario:** a crash between create and write leaves an empty locator; every subsequent start refuses it. **Fix row — xhard, coordinate with OWNERCLAIM:** publish complete, synced bytes under an exclusive home-scoped claim and handle interrupted temporary files. File: `portfolio/execution_host.py`. Acceptance: interrupt publication before the final name appears; restart succeeds, while two concurrent live starters still yield one owner. Plausible mistake: `os.replace` overwrites a live owner’s locator.

3. **Completed authenticated socket receipts permanently occupy the scanned IPC directory.** [execution_host.py:1186](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1186) retains a `socket-intent` for each admitted call and [execution_host.py:1219](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1219) publishes its response. [ipc_retention.py:99](/private/tmp/otto-audit-tree/src/otto/portfolio/ipc_retention.py:99) treats every intent as live, so even an aged terminal response cannot be pruned; it sorts those responses on each sweep. Sustained socket traffic grows disk use and sweep cost without bound. RET names unknown and pending responses, but does not cover these *completed socket* records. **Fix row — xhard:** compact terminal socket receipts while retaining their replay fence and exact-scope recovery behavior. Files: `portfolio/ipc_retention.py`, `portfolio/execution_host.py`, `portfolio/manager_journey_client.py`. Acceptance: aged terminal socket traffic no longer grows the scanned directory, and reuse of a retired token is refused. Plausible mistake: deleting the intent and permitting a second effect.

4. **The stop marker can be seen before its explanation is written.** [cli.py:915](/private/tmp/otto-audit-tree/src/otto/hostctl/cli.py:915) writes directly to `service-stop`; [project_service.py:186](/private/tmp/otto-audit-tree/src/otto/hostctl/project_service.py:186) stops on existence, while [project_service.py:278](/private/tmp/otto-audit-tree/src/otto/hostctl/project_service.py:278) reads the explanation once into the draining snapshot. **Scenario:** the owner observes a newly created, empty marker, closes, and publishes a final status without the requested reason even after the write finishes. **Fix row — normal:** publish the private marker by same-directory temporary file and replace. Files: `hostctl/cli.py`, stop/status tests. Acceptance: pause before replacement; the owner remains serving until the complete marker appears, then closed status contains the reason.

5. **Closed-owner recovery mistakes PID reuse for live custody.** [execution_host.py:1846](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1846) and [execution_host.py:1930](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1930) use `kill(pid, 0)` alone, unlike normal startup’s process-start and boot comparison at [execution_host.py:1038](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1038). **Scenario:** an owner exits, its PID is reused, and exact retained worker recovery is refused as “another live owner.” **Fix row — normal:** use the startup identity comparison in both recovery paths. File: `portfolio/execution_host.py`. Acceptance: a stale locator naming a reused live PID permits exact recovery; a matching live owner still refuses it.

6. **A malformed status object crashes the status reader.** [service.py:119](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:119) converts JSON/read errors to `unavailable`, but [service.py:128](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:128) assumes `holder` is a mapping and [service.py:141](/private/tmp/otto-audit-tree/src/otto/hostctl/service.py:141) converts an unchecked heartbeat interval. **Scenario:** syntactically valid damaged or older status such as `{"holder":"bad"}` raises `AttributeError` instead of reporting owner state. **Fix row — normal:** validate the status schema and field types before interpreting them. File: `hostctl/service.py`. Acceptance: malformed private status files return `unavailable` with a reason; a current heartbeat still reports running.
