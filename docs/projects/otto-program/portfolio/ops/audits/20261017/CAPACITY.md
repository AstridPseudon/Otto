## 1. Findings

**1. A native worker failure has no general fence retirement path.**

- **Evidence:** Claude records a native error as `failed` ([claude_adapter.py:455](/private/tmp/otto-audit-tree/src/otto/agents/claude_adapter.py:455)). Recovery returns a non-success result without completing the Due ([execution.py:1454](/private/tmp/otto-audit-tree/src/otto/portfolio/execution.py:1454)); the host retains its custody hold ([execution_host.py:408](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:408)). The manager’s general gone-group recovery requires a retained `unknown` result ([execution_host.py:551](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:551)); capacity-failure recovery also requires a specific `unknown` envelope ([worker_custody.py:147](/private/tmp/otto-audit-tree/src/otto/portfolio/worker_custody.py:147)).
- **Scenario → outcome:** A Claude worker receives a native error after its work process starts. Once the recorded group is proven gone, the host returns its slot but keeps the same-project fence. Repeated manager `recover` calls cannot retire that `failed` result. Further workers in the project wait. This is a sibling of KILLFENCE: its recovery covers a qualified `unknown` attempt, not this retained `failed` outcome.
- **Proposed fix row — xhard:** Give the assigned manager an exact, durable disposition for terminal non-success results, preserving the failed result and forbidding provider replay. Files: `execution_host.py`, `manager_journey_service.py`, worker custody/disposition code, focused tests. **Acceptance:** a retained Claude `failed` result with a proven-gone group can be dispositioned once; its fence clears, its history remains failed, and no provider call occurs. A plausible mistake is treating `failed` as proof of no effects and permitting a second provider turn.

**2. A failed process-group pin can leave both slot and fence held indefinitely.**

- **Evidence:** The pin hook swallows recording errors and lets launch continue ([owner_runtime.py:31](/private/tmp/otto-audit-tree/src/otto/agents/owner_runtime.py:31), [owner_runtime.py:53](/private/tmp/otto-audit-tree/src/otto/agents/owner_runtime.py:53)); an existing test confirms an exited process pins nothing ([test_capacity_pool.py:409](/private/tmp/otto-audit-tree/tests/test_capacity_pool.py:409)). With no record, `_reconcile_hold` cannot prove exit ([execution_host.py:770](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:770)), while general manager recovery refuses a missing recorded group ([execution_host.py:608](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:608)).
- **Scenario → outcome:** **Inference from those paths:** pinning fails before the worker receives useful input, but its already claimed attempt later retains an `unknown` result. The child exits. No group record exists, so reconciliation retains the slot and fence across owner restart; the manager’s gone-group command cannot clear them. One such attempt can permanently reduce worker capacity.
- **Proposed fix row — xhard:** Make durable group pinning a required step before useful work, or persist equally strong terminal pre-input proof when pinning fails and the child is stopped. Files: `owner_runtime.py`, `execution_host.py`, native launch adapters, focused tests. **Acceptance:** inject a pin failure, restart the owner, and show no live child, charged slot, or unresolved fence for a proven pre-input failure; an unproven live child must remain held. A plausible mistake is releasing capacity merely because pinning failed while the child continues running.

**3. PID reuse prevents release even after the recorded group is empty.**

- **Evidence:** `_group_state` checks that the PGID has no members, then returns `reused` when the leader PID has a different birth identity ([execution_host.py:739](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:739), [execution_host.py:753](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:753)). Only `gone` frees a slot ([execution_host.py:770](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:770)); manager recovery likewise requires `gone` ([execution_host.py:611](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:611)). A test currently asserts retention for an empty group with a reused PID ([test_capacity_holds.py:121](/private/tmp/otto-audit-tree/tests/test_capacity_holds.py:121)).
- **Scenario → outcome:** A killed worker’s group disappears, then its leader PID is assigned to an unrelated, long-lived process in another group before reconciliation. The old PGID is empty, yet Otto keeps charging the slot and refuses manager fence recovery for as long as that unrelated PID lives.
- **Proposed fix row — xhard:** Treat *empty recorded PGID plus mismatched leader birth* as proof that this recorded group is gone; retain the hold if any old PGID member exists. Files: `execution_host.py`, `tests/test_capacity_holds.py`. **Acceptance:** reverse the empty-group/PID-reuse test while the “leader gone but group member alive” test still holds. A plausible mistake is releasing on PID mismatch alone while a descendant remains in the original group.

**4. An execution in project A delays activation of unrelated project B.**

- **Evidence:** A queued job enters `_executions` at admission ([execution_host.py:837](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:837)). Host-client custody returns true for *any* queued or running execution before comparing project IDs ([project_service.py:73](/private/tmp/otto-audit-tree/src/otto/hostctl/project_service.py:73)); activation is deferred ([project_service.py:115](/private/tmp/otto-audit-tree/src/otto/hostctl/project_service.py:115)), and direct view installation has the same global check ([project_services.py:81](/private/tmp/otto-audit-tree/src/otto/portfolio/project_services.py:81)).
- **Scenario → outcome:** A has a long-running or merely queued turn; an operator activates B. B remains pending although A’s retained holds are correctly project-scoped. **Inference:** this shared activation boundary limits unrelated project availability; the comments show it is deliberate, so changing it requires checking live router safety.
- **Proposed fix row — xhard:** Permit unrelated activation during A’s execution with an exact project-bound view installation boundary. Files: `hostctl/project_service.py`, `portfolio/project_services.py`, activation tests. **Acceptance:** B activates while A runs or queues; A’s own activation remains held and A’s in-flight result still routes to its original view. A plausible mistake is replacing shared routing state underneath A’s owner callbacks.

**5. Capacity status understates the combined turn limit.**

- **Evidence:** The default policy permits six worker units plus two manager-reserve units ([capacity.py:21](/private/tmp/otto-audit-tree/src/herzchen/fleet/capacity.py:21), [capacity.py:55](/private/tmp/otto-audit-tree/src/herzchen/fleet/capacity.py:55)), but status labels `manager_units`—six by default—as `native_capacity.total_limit` ([project_service.py:484](/private/tmp/otto-audit-tree/src/otto/hostctl/project_service.py:484), [project_service.py:492](/private/tmp/otto-audit-tree/src/otto/hostctl/project_service.py:492)).
- **Scenario → outcome:** Six workers and two managers can be admitted across distinct workspaces, while status reports eight active against a “total limit” of six. Operators and capacity assertions see a false over-limit condition.
- **Proposed fix row — normal:** Report the combined turn ceiling separately from each role’s ceiling. Files: `hostctl/project_service.py`, status test. **Acceptance:** under the default policy, status reports a combined turn ceiling of eight, worker ceiling six, and manager ceiling six.

## 2. Checked and sound

- **Succeeded:** Owner recovery completes the Due; host finish removes its fence and settles its slot ([execution.py:1467](/private/tmp/otto-audit-tree/src/otto/portfolio/execution.py:1467), [execution_host.py:415](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:415)).
- **Failed before provider:** A refusal before the owner operation releases its provisional slot; a refusal inside that operation before a gateway attempt ends at host finish with no fence ([execution_host.py:936](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:936), [execution_host.py:945](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:945)). A claimed attempt classified `unknown` follows the unknown path instead.

- **Unknown:** Host retains the fence and slot while group exit is unproven; proven exit frees only the slot. The assigned manager’s exact `unknown` disposition clears the fence through `restore_execution` ([execution_host.py:777](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:777), [execution_host.py:634](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:634)).
- **Killed:** A recorded group proven gone returns its slot; a captured, qualified `unknown` needs manager recovery to clear its fence. Process death alone does not authorize replay.
- **Owner restart:** Store reservations are adopted; known Dues are restored before the pump starts, and startup reconciles dead groups ([capacity.py:218](/private/tmp/otto-audit-tree/src/herzchen/fleet/capacity.py:218), [project_services.py:178](/private/tmp/otto-audit-tree/src/otto/portfolio/project_services.py:178), [execution_host.py:1021](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:1021)).
