## Findings

1. **The manager journey suite skips in the default gate.** [tests/test_manager_journey_service.py:54](/private/tmp/otto-audit-tree/tests/test_manager_journey_service.py:54) skips the whole class if its optional fixture is absent. Its default path resolves to `/private/controller/manager_server_baseline.py`, which is absent in this checkout. The checked-in pytest runner does not set `OTTO_OWNER_SERVICE_TEST_FIXTURE` and treats skips as clean ([land.sh:212](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:212), [land.sh:333](/private/tmp/otto-audit-tree/ops/bootstrap/land.sh:333)). **Scenario:** with that variable unset, all 39 class tests skip while a manager journey change can pass the file sweep. **Why it matters:** service routing, retained worker, review, and recovery claims receive no gate evidence. **Fix row — normal:** make the fixture checked-in and mandatory, or retarget the tests to the installed service. Files: the test, its fixture, `land.sh`. Acceptance: running the file with the variable unset executes all 39 tests; a missing fixture fails the gate instead of skipping. Inference: an externally supplied gate variable could make a particular run execute them; the checked-in gate does not ensure it.

2. **Automatic dispatch tests force the final admission check to succeed.** [tests/test_fleet_dispatch.py:488](/private/tmp/otto-audit-tree/tests/test_fleet_dispatch.py:488), :501, :547 and :584 patch `recheck_execution_admission` to return `"admitted"` before `_start_ready_executions`. The product rechecks both at admission and immediately before the operation ([execution_host.py:914](/private/tmp/otto-audit-tree/src/otto/portfolio/execution_host.py:914), :958). **Scenario:** a task changes after the pump queues it but before launch; these tests still record a launch because their patch suppresses the real recheck. **Why it matters:** the tests cannot catch an unadmitted automatic start at this boundary. **Fix row — normal:** use a real owner/admission fixture for pump-to-launch tests; leave only the provider as a stand-in. Files: `test_fleet_dispatch.py` and fixture support. Acceptance: change task content between pump and launch; no provider call occurs, while a metadata-only revision remains launchable. The separate direct recheck test at [test_execution_operations.py:146](/private/tmp/otto-audit-tree/tests/test_execution_operations.py:146) does not cover that race.

3. **Assessment-policy hydration is proved against invented coverage.** [tests/test_hostctl_serve.py:143](/private/tmp/otto-audit-tree/tests/test_hostctl_serve.py:143) constructs a scope and criterion, then patches both `OttoAssessment` and `AssessmentModule` at :166–167, :192–193 and :202–203. Production obtains scope coverage from those components ([serve.py:282](/private/tmp/otto-audit-tree/src/otto/hostctl/serve.py:282)) and binds the resulting aliases at :369–375. **Scenario:** the run document names `T1/C01` but the real Store has no corresponding scope; the test’s invented coverage still makes hydration pass. **Why it matters:** a green policy test can conceal a project that cannot bind its acceptance criterion. **Fix row — normal:** create real Store scopes and criteria, then exercise hydration without product-method patches. Files: `test_hostctl_serve.py`, its Store fixture. Acceptance: removing the scope makes hydration refuse `T1/C01`; restoring it resolves the exact criterion.

4. **Other focused tests replace product behavior outside the permitted person/model seam.** Examples: [test_ask_socket_wait.py:95](/private/tmp/otto-audit-tree/tests/test_ask_socket_wait.py:95) replaces caller authorization and asking-session validation; [test_execution_continuity.py:162](/private/tmp/otto-audit-tree/src/otto/portfolio/tests/test_execution_continuity.py:162) supplies both operating-setup readiness results; [test_hostctl_portfolio.py:60](/private/tmp/otto-audit-tree/tests/test_hostctl_portfolio.py:60) supplies setup composition success; [test_fleet_custody.py:209](/private/tmp/otto-audit-tree/tests/test_fleet_custody.py:209) substitutes `LabFleet`, owner ports and the facade server. Lower-risk no-call or failure cases also patch `reconfigure` ([test_manager_advisor_paused_host.py:114](/private/tmp/otto-audit-tree/tests/test_manager_advisor_paused_host.py:114)) and `supervise` ([test_hostctl_project_service.py:90](/private/tmp/otto-audit-tree/tests/test_hostctl_project_service.py:90)); the latter asserts the supplied `"held"` result. **Scenario:** a foreign ask caller or stale operating setup can receive the test’s selected outcome without the real authorization or setup reader running. **Why it matters:** these tests establish branch wiring, while their names and green results can be read as proof of the owner path. **Fix row — normal:** replace product stubs with real disposable owner/domain fixtures; retain person/model stand-ins and clearly scoped failure injection only after reconciling it with the stated patch rule. Files: the cited tests and shared fixtures. Acceptance: a gate check rejects product-method replacement in these tests, and foreign-caller/stale-setup cases fail through real product methods.

5. **The admission hold assertion can pass before the owner sees the request.** [tests/test_operator_admission.py:281](/private/tmp/otto-audit-tree/tests/test_operator_admission.py:281) submits a request, sleeps 150 ms, then checks that the request remains and presence was not prompted at :285–288. It releases the synthetic dispatch hold at :289. **Scenario:** if owner polling starts after the sleep, those assertions pass even with admission deferral broken; the owner processes the request only after the hold clears. **Why it matters:** the test can falsely validate the single-prompt hold behavior. This is a test sibling of ADMITHELD, whose row does not remove this timed observation. **Fix row — normal:** drive a real owner poll while the hold is open and inspect the retained request before releasing it. Files: `test_operator_admission.py`. Acceptance: no sleep is needed, and bypassing deferral makes the test fail.

6. **Two concurrency tests turn scheduling delay into failure.** [tests/test_execution_host_manager_turn_queue.py:113](/private/tmp/otto-audit-tree/tests/test_execution_host_manager_turn_queue.py:113) allows only 250 ms to acquire a shared lock, then fails at :124 even if the queued turn releases it later. [tests/test_embedded_host_heartbeat.py:119](/private/tmp/otto-audit-tree/tests/test_embedded_host_heartbeat.py:119) sleeps 5.2 seconds and requires a heartbeat at that instant; a delayed heartbeat thread can fail the test despite subsequently correct behavior. **Why it matters:** ordinary runner load can produce reds unrelated to the asserted lock and heartbeat invariants. **Fix row — normal:** synchronize on the queued turn’s lock-release state and use a controlled clock or observed heartbeat publication. Files: both cited tests. Acceptance: delayed scheduling changes neither result; a held lock or absent heartbeat still fails.
