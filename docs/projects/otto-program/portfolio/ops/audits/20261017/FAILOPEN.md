1. **A conflicting review or owner policy can mark the wrong plan ready.**  
   **Evidence:** [reviewed_activation.py:179](/private/tmp/otto-audit-tree/src/otto/portfolio/reviewed_activation.py:179) takes the first plan-reference alias; [reviewed_activation.py:191](/private/tmp/otto-audit-tree/src/otto/portfolio/reviewed_activation.py:191) does the same for digests. [reviewed_activation.py:267](/private/tmp/otto-audit-tree/src/otto/portfolio/reviewed_activation.py:267) uses `plan_ref or required_plan_ref`; [reviewed_activation.py:278](/private/tmp/otto-audit-tree/src/otto/portfolio/reviewed_activation.py:278) can then mark the project ready.  
   **Scenario:** An approved review contains `plan_ref=A` and `reviewed_plan_ref=B`, while the adopted policy contains `plan_ref=A` and `required_plan_ref=B`. With a valid A and eligible predecessor, `read(..., plan_ref=A)` ignores both contradictory B pins and reports ready. **Inference:** activation can proceed on a plan the review or policy also identifies as different.  
   **Fix row — normal:** Reject conflicting aliases when reading reviews and adopted policy. File: `src/otto/portfolio/reviewed_activation.py`. Acceptance: contradictory refs or digests make readiness held; consistent legacy aliases still pass. The contradictory case passes before the fix.

2. **Release checks and decisions can attach another candidate to a repository.**  
   **Evidence:** `select_candidate` stores the selected ref at [release_records.py:299](/private/tmp/otto-audit-tree/src/otto/engineering/release_records.py:299). The check and decision paths use `candidate_ref or record.payload.get("candidate_ref")` at [release_records.py:309](/private/tmp/otto-audit-tree/src/otto/engineering/release_records.py:309) and [release_records.py:324](/private/tmp/otto-audit-tree/src/otto/engineering/release_records.py:324). The check path compares the fetched candidate only with the caller’s value at [release_records.py:315](/private/tmp/otto-audit-tree/src/otto/engineering/release_records.py:315), then stores it on the repository.  
   **Scenario:** Select candidates A and B for two repositories; call `record_required_check` or `record_manager_decision` for repository A with `candidate_ref=B`. The methods never compare B with A’s retained `candidate_ref`. The resulting repository check or decision names B. **Inference:** release evidence can be attributed to the wrong candidate.  
   **Fix row — xhard:** Bind both operations to the repository’s exact selected candidate and its source set before any public write. File: `src/otto/engineering/release_records.py`. Acceptance: B is refused for A, with no repository or Decisions event; A succeeds. Plausible local mistake: validating only the candidate ID, or validating after the public Decisions write, leaves the cross-domain candidate pin broken.

The guard rejects a supplied wrong digest at [release_records.py:598](/private/tmp/otto-audit-tree/src/otto/engineering/release_records.py:598).  
   **Scenario:** Call `record_manager_decision` with the selected candidate but a wrong, non-null source digest. It writes a Decisions record, then rejects the release-record update. **Inference:** a caller sees refusal while a public decision remains.  
   **Fix row — xhard:** Validate all pins before the Decisions write and make a later repository-write failure reconcilable. File: `src/otto/engineering/release_records.py`. Acceptance: a wrong digest leaves both event streams unchanged; a forced repository-write failure cannot leave an unexplained public decision. Plausible local mistake: moving this one guard earlier still leaves a half-write if the repository CAS fails afterward.

4. **Actor deserialization promotes missing or nonboolean authentication to true.**  
   **Evidence:** [model.py:383](/private/tmp/otto-audit-tree/src/herzchen/contracts/model.py:383) constructs `AuthenticatedActor` with `bool(value.get("authenticated", True))`. The constructor rejects only falsy values at [model.py:376](/private/tmp/otto-audit-tree/src/herzchen/contracts/model.py:376). The decoder is used for Evidence read grants at [reads.py:115](/private/tmp/otto-audit-tree/src/herzchen/content/reads.py:115) and retained operation actors at [operations.py:353](/private/tmp/otto-audit-tree/src/herzchen/kernel/operations.py:353).  
   **Scenario:** An otherwise shaped actor record omits `authenticated`, or supplies `"false"` as a string. Both decode as `authenticated=True`. **Inference:** consumers of a retained or serialized actor can treat a weaker record as an authenticated fact; this does not establish that an external caller can alter the admitted Store.  
   **Fix row — normal:** Require the field to be the boolean `True` when decoding an authenticated actor; handle any proven historical shape through an explicit migration. File: `src/herzchen/contracts/model.py`. Acceptance: missing, string, and numeric values are rejected; boolean `True` succeeds. All three weak shapes are accepted before the fix.

File: `src/otto/attention.py`; update `tests/test_due_configuration.py`. Acceptance: missing support or expected identity is rejected; explicit matching evidence passes. 6. **Direct Due mutators skip owner checks when identity is omitted (latent API gap).**  
   **Evidence:** `reconfigure` checks its actor only when supplied at [attention.py:2459](/private/tmp/otto-audit-tree/src/otto/attention.py:2459). `_scope_error` checks lifecycle owner only when supplied at [attention.py:2786](/private/tmp/otto-audit-tree/src/otto/attention.py:2786); `complete` and `stop` call it with optional owner fields at [attention.py:3090](/private/tmp/otto-audit-tree/src/otto/attention.py:3090) and [attention.py:3195](/private/tmp/otto-audit-tree/src/otto/attention.py:3195).  
   **Scenario:** A caller holding the Due port omits `actor` from `reconfigure`, or `lifecycle_owner` from `stop`; with otherwise valid state and request, the mutation proceeds. A matching in-flight request similarly permits ownerless `complete`. **Reachability limit:** the current production callers I traced supply the owner, so this is a direct API weakness, not a demonstrated host-lane bypass.  
   **Fix row — normal:** Require the current lifecycle owner on these mutators and reject omitted identity before mutation. File: `src/otto/attention.py`. Acceptance: direct calls without owner are refused; current bound callers succeed. The omission cases succeed before the fix.
