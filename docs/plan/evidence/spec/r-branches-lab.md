## Index and scope

The 16 lab branches listed in `../BRANCH-LOG.md:1–38` are BOOTCFG, BOOTLAND, CLIARGS, DISTURB, INTEG-PROCLIFE-PL3, LABPIN, LANDBATCH, LANDPROOF, OBSOWNER, PROOFDOC, REALSTAGE3, ROLEIDS, ROOTFILE, STAGE2CLIENT, TESTPATCH, and XFERMAP. Their logged commits are recorded in the same ranges. **The relevant test filenames recur across all 16 lab snapshots**, including `test_landing.py`, `test_bootstrap_gate.py`, `test_work_readiness.py`, and the ask and status suites. This is a shared test corpus, not 16 independent proofs; branch differences are captured by the commit log, not by a separate set of minimal-tool contracts.

I use “without owner service” to mean the test does not require a separately installed/running Otto owner process. A test may still instantiate Otto’s in-process Store or service fixtures. I did not run tests.

## 15 tests I’d carry over as specs

These names identify existing contracts to adapt; they are not a claim that Otto’s current implementations should be copied wholesale.

1. `test_blocked_dep_waits` — block dispatch until dependencies complete.
2. `test_terminal_task_lifecycle_is_not_dispatchable` — don’t restart completed/withdrawn work.
3. `test_projects_and_gates_flip_readiness_on_completion` — readiness changes when prerequisites finish.
4. `test_runner_checks_rebased_commit_not_lab_commit` — check the rebased result.
5. `test_admitted_gate_check_uses_rebased_commit` — validate the exact commit to land.
6. `test_failed_admitted_check_returns_lab_to_worker` — failed checks do not land.
7. `test_a_flaky_failure_is_listed_not_refused` — record a non-reproducible failure.
8. `test_a_failure_that_reproduces_alone_is_refused` — reproducible new failure blocks landing.
9. `test_crash_restart_keeps_one_session_and_requires_explicit_resume` — preserve draft state across restart.
10. `test_simultaneous_canonical_edit_conflicts_without_overwrite` — stale check-in cannot overwrite newer spec.
11. `test_replayed_finish_receipt_is_idempotent_and_remains_committed` — repeated check-in does not publish twice.
12. `test_answered_worker_continuation_dispatches_once_and_replay_is_inert` — message answer resumes once.
13. `test_missed_slots_coalesce_and_paused_schedule_is_held` — define reminder catch-up behavior.
14. `test_session_named_by_codex_and_work_committed` — persist the spawned session reference.
15. `test_resume_continues_the_session` — resume that session instead of starting a duplicate.

For the minimal design’s distinctive **manager turn-end check**, add a new acceptance test; the inspected canon tests cover adjacent status and timeout behavior, not that exact rule.
