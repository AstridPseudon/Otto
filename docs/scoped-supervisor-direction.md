responsibility's already-bound controlling direction**. It does not author the
supervisor's own instructions or the project-level direction binding. Read those
surfaces separately. An unbound project/supervisor surface does not establish
whether the manager responsibility is bound. First binding, generic
`project-authoring`, portfolio authoring, new activation and messaging are outside
this facade.

## Own-client operation recipe

Use the own issued locator and installed entrypoint; for the current controller
the entrypoint is `controller/orchestrator_client_ctl.py`. CLI shape is:

```text
python3.11 <installed-entrypoint> --binding <own-binding.json> supervisor-direction-read --project-id <exact-supervised-project>
python3.11 <installed-entrypoint> --binding <own-binding.json> supervisor-direction-draft --project-id <exact-supervised-project> --request-key <distinct-draft-key> --request <complete-draft-JSON>
python3.11 <installed-entrypoint> --binding <own-binding.json> supervisor-direction-read --project-id <exact-supervised-project>
python3.11 <installed-entrypoint> --binding <own-binding.json> supervisor-direction-adopt-and-continue --project-id <exact-supervised-project> --request-key <distinct-adopt-key> --request <six-pin-JSON>
python3.11 <installed-entrypoint> --binding <own-binding.json> request-status --request-id <original-handle>
```

Each read returns `direction_surface: manager-responsibility`, `subject_ref`,
current manager assignment/generation/schedule and exact `direction` refs. The
manager responsibility binding for any actual project must be read successfully
through this route before claiming applicability. Cached state is not a fresh pin.

Draft JSON contains exactly:

```json
{"content": {"schema": "herzchen.instructions.v1", "...": "complete approved instruction document"}, "expected_revision": "<read.direction.latest_ref.revision>"}
```

The placeholder is explanatory: preserve the complete valid document, supporting
refs and constraints. The canonical JSON payload is bounded to 65536 bytes;
contents are never silently clipped. Draft is saved, not adopted. After the fresh
post-draft read, adopt JSON contains exactly:

```json
{
  "document_ref": {"...": "draft.draft.revision_ref"},
  "expected_binding_ref": {"...": "fresh-read.direction.binding_ref"},
  "expected_direction_ref": {"...": "fresh-read.direction.latest_ref"},
  "expected_manager_ref": {"...": "fresh-read.manager_assignment_ref"},
  "expected_manager_generation": 1,
  "expected_schedule_id": "<fresh-read.manager_schedule_id>"
}
```

Use the returned actual generation, not the example's number. Never omit an exact
ref field. This requires the manager's current native effect to be settled. It
may preserve an active worker on its original Due/assignment/native/context pins.
It commits direction, corresponding BASE, exact adoption/application receipts and
one prepared manager callback atomically, then publishes the current bootstrap
assignment/guide/mandate/schedule/head. Canonical replay repairs publication loss
without preparing or sending another effect; rollback does not publish a staged
head. The manager adoption bridge requires canonical unchanged-identity resource
history. General stale assignment checks remain exact.

Success reports `delivery: prepared-not-started`. Use the existing own route once:

```text

```

This starts only the current prepared manager, through existing capacity/writer
fences; it adds no worker allowance. Retain each original outer handle after a

absence or permission to resend. A saved draft, canonical adoption, prepared
callback, native start, actual acknowledgement, worker result and task acceptance
are separate. Verify the manager actually reads the exact direction/BASE and
continues its authorized work. A delayed original worker result must use the
service's current manager selector and merge into an unstarted directive callback;
it must not reactivate the historical parent or create a second writer.

No push sender is added here. Receipt-inspection remains the delivered transport
capability. Disposable real-owner/synthetic adapter checks do not prove installed
