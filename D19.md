# D19 decision: manager journey assertions

The manager journey suite now uses the in-repository `HostOwnerService` and the product `install_manager_journey_service` hook with a disposable owner Store and fake provider adapter.

- Retired `test_baseline_real_run_worker_starves_nested_report_until_worker_returns`. Its elapsed-time and file-absence checks inferred starvation from a delay. Replaced it with an event-driven check that waits for the fake worker provider to enter its blocked state, sends a manager report through `otto.hostctl.manager_client`, observes the report commit, then releases the worker.
- Removed the baseline-only `project_scope_denied` assertion against `server.handle`. That handler is now the maintained `HostOwnerService`; its generic command path does not implement the retired baseline route. The same test retains the journey's product-backed lifecycle read and forged project/task scope rejection assertions.
- Updated the repeated `run-worker` assertion to the maintained caller response shape: `outcome == "retained"` and `handles.start` equals the original retained handle. The owner effect and replay identity are unchanged.
- Restored the starvation journey's terminal worker assertion (`outcome == "succeeded"`) while keeping its event-driven report-commits-before-release check. No elapsed-time starvation expectation was added.
- In the intermediate-finish journey, `review.json` now stores the actual `finish-task` response, so the existing pending assertion checks that operation. The subsequent manager completion, settlement, and continuation assertions remain in place.
- Updated one prompt wording assertion in that continuation journey to match the current owner-delivered instruction, “Advance only genuinely unfinished tasks through ordinary delegation and review.” The prior phrase was absent from the actual continuation prompt and raised inside the fake provider, turning the adapter result into an unknown delivery; the test still asserts the same continuation instruction and subsequent admitted worker/completion effects.
- The next task is launched as a nested worker under that manager turn, so its successful terminal response has no separate `manager_result_notification`. The journey now asserts the nested worker response itself succeeds, while retaining the subsequent parent continuation and task-state assertions.
- Replaced answer/route method substitutions with a real help request/resolution, worker reroute, and retained-schedule retry through the installed manager service.
- Replaced `save_due` thread instrumentation and `_journal` wrapping with assertions over persisted Due, report, and assessment-pool state. Refusal, retained-handle, and no-repeat assertions remain.
- Replaced patched historical acceptance with persisted assessment, allowance, and completion records. Replaced patched content reads with a stored tampered correction SOURCE and owner metadata link; the valid link is restored before the later genuine corrective completion.
- The genuine corrective `review-task` now asserts its real `finish-task` response is `completed`. The former `pending` expectation came from the substituted settlement behavior; the maintained caller returns the committed completion. Its manager continuation reports the completion intent as `replayed` because that same completion has already committed, then admits the settlement continuation. The journey asserts all three outcomes.
- Replaced mocked `read_due` with a persisted unsettled Due fixture and verified that the held continuation leaves it unchanged.
- Updated the observed worker model assertion from the retired external provider model to `gpt-test`, the model configured in this disposable owner fixture and reported by its adapter.
- Additional directly required file: `src/otto/hostctl/manager_client.py` now omits inactive `route` CLI options when building the maintained caller request. The parser supplies those options as `None`, which violated the owner's exact `reroute`/`retry` request schema and made the real route path return unknown before dispatch.
- Additional directly required files: `src/otto/hostctl/manager_client.py` also exposes the existing identity-bearing `project-lifecycle-read` command to launched managers; the real nested-manager CLI previously exited in argparse before it could reach the owner. `src/otto/portfolio/manager_journey_service.py` now returns the known invalid worker operation profile as an explicit no-effects error before worker preparation; previously its deterministic pre-effect validation exception crossed the retained socket boundary and became `unknown`.
- Routed the final `finish-project` in the continued-manager journey through the maintained manager caller. The orchestrator file lane deliberately does not implement that manager-only command; the journey still asserts terminal completion/readback and unchanged provider count.
- Restarting journey hosts now restores the owner caller-binding hooks and reattaches the maintained service before use. The former test-only bare `ExecutionHost` restart dropped those hooks, so restart checks were observing transport-unavailable instead of testing retained owner recovery.
- The unknown-send restart journey now replays the same request through the reattached owner service after restart. The prior native caller subprocess remains tied to its closed host socket; using that stale process returned transport-unavailable before owner recovery. The response exposes the retained handle as `handles.start`; assertions still require the exact handle, unchanged Due, zero added provider calls, and a held distinct key.

The product-backed pending finish assertion now reads the `finish-task` response rather than the preceding `review-task` response. The starvation worker-success assertion restores the dropped terminal guarantee. The observed-model expectation follows the fixture's configured fake model. No substantive refusal, retained-effect, budget, or no-repeat protection was removed.
